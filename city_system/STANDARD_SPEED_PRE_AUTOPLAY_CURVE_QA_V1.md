# Standard-speed Pre-Autoplay Curve QA V1

Date: 2026-09-23
Status: STATIC QA COMPLETE / RUNTIME AUTOPLAY STILL REQUIRED

## Scope

This is **not** a claim that a Civilization runtime autoplay has already been executed.

The repository currently contains structural validators but no game-engine autoplay harness. This pass therefore checks the locked/provisional Science and Culture cost curves before runtime testing.

Inputs:

- `tech_reference/VP_SCIENCE_COST_CURVE_ADAPTATION_V1.csv` — 109 technologies / 13 project eras
- `civics_reference/VP_CULTURE_COST_CURVE_ADAPTATION_V1.csv` — 72 civics / 13 project eras

Output table:

- `city_system/STANDARD_SPEED_PRE_AUTOPLAY_CURVE_QA_V1.csv`

## Metrics

For each era the table records:

- node count
- total era cost
- mean cost
- minimum and maximum node cost
- boundary ratio = first node of current era / last node of previous era
- total-era-cost ratio to previous era
- mean Technology cost / mean Civic cost

Static flags are deliberately conservative. A flag means `watch in runtime`, not `change now`.

## 1. Era-boundary continuity

The largest explicit boundary jump is Ancient -> Classical:

- Science: 130 -> 200 = 1.538x
- Culture: 90 -> 140 = 1.556x

All later Science boundaries are 1.300x or lower.
All later Culture boundaries are 1.273x or lower except Industrial -> Modern at 1.169x, which is still well below the Ancient -> Classical step.

Decision:

- Keep the current values for now.
- Mark Ancient -> Classical as a runtime pacing watch.
- Do not smooth the boundary before observing actual Science/Culture income growth in play.

## 2. Industrial bulk is caused by node count

Industrial has the largest roster density:

- 16 technologies, total Science cost 136,000
- 9 civics, total Culture cost 50,400

Compared with Enlightenment totals:

- Science total ratio = 4.317x
- Culture total ratio = 2.762x

However the individual-node boundary itself remains moderate:

- Science 5800 -> 6500 = 1.121x
- Culture 4000 -> 4700 = 1.175x

Therefore the likely issue, if Industrial pacing is too slow, is not a single bad cost jump. It is the **number of nodes combined with the per-node curve**.

Decision:

- Do not globally reduce Industrial node costs yet.
- During runtime autoplay measure turns spent in Industrial separately from node completion rate.
- If Industrial is too long, first examine required-path density and Science/Culture income acceleration before applying an era-wide discount.

## 3. Technology/Civic relative scale

Mean Technology cost divided by mean Civic cost is relatively stable for most eras, approximately 1.40-1.58.

The largest value occurs in Atomic:

- mean Technology = 19,000
- mean Civic = 11,500
- ratio = 1.652

This is flagged `SCIENCE_CULTURE_RATIO_WATCH`.

This alone is not evidence that Atomic Science costs are too high because Science and Culture per turn are generated by different buildings, specialists, Great People and policies.

Decision:

- no numerical change before runtime income data exists.

## 4. Why total-era ratios are not direct balance verdicts

Total-era cost changes strongly with node count. For example Atomic Science total falls relative to Modern even though every Atomic technology is more expensive, because Atomic has only 5 technologies versus 12 Modern technologies.

Therefore runtime balance must track at least:

1. turns per researched Technology/Civic
2. turns spent between era-entry milestones
3. number of optional versus effectively required nodes
4. Science/Culture per turn at era entry and exit
5. AI and human-equivalent completion distributions

A simple era-total comparison is only a bottleneck detector.

## 5. Runtime watch list

### Watch A — Ancient -> Classical

Check whether players stall immediately after the Ancient tree because income has not yet risen enough to match the 1.54-1.56x boundary increase.

### Watch B — Industrial density

Check whether 16 technologies and 9 civics create an era-duration spike even though adjacent-node prices are smooth.

### Watch C — Atomic Science/Culture divergence

Check whether Science progression falls materially behind Civic progression. Do not assume that the 1.652 cost ratio is itself wrong.

### Watch D — equal-cost unit upgrades

Runtime autoplay must also observe the three unit upgrade edges already tagged in `FINAL_UNIT_UPGRADE_COSTS_V2_VP.csv`:

- Trebuchet -> Bombard: 10 Gold
- Rifleman -> Infantry: 10 Gold
- Landship -> Tank: 10 Gold

These arise from equal V3 Production costs under the source-exact VP upgrade formula.

## 6. Global multiplier rule

No Science, Culture or Production global common multiplier is changed in this static pass.

A common multiplier can be justified only after runtime evidence shows that the **whole game** is systematically too fast or too slow. Local era bottlenecks should not be hidden by a global multiplier.

## Final verdict

**STATIC PASS WITH RUNTIME WATCHES.**

The current curves are internally monotonic and sufficiently smooth to proceed to actual Standard-speed runtime testing. The strongest watch areas are Ancient -> Classical boundary pacing, Industrial roster density, Atomic Science/Culture relative pacing, and the three minimum-cost unit upgrade edges.
